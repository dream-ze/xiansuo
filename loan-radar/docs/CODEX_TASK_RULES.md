# Codex 开发规则

## 1. 项目名称

线索雷达

## 2. 当前阶段

当前阶段是 Demo 可成交版。

目标是跑通后端主链路：

监控源管理 → 采集任务 → Mock 采集 → 帖子池 → 评论池 → 线索识别 → 线索池 → 今日获客报告 → CSV 导出。

## 3. 绝对禁止事项

当前阶段禁止：

- 不要开发 CRM
- 不要开发员工管理
- 不要开发复杂权限
- 不要开发自动发布
- 不要开发复杂 AI 工作台
- 不要引入复杂智能体框架
- 不要接真实小红书/抖音/知乎全量采集
- 不要做自动登录
- 不要做反爬绕过
- 不要做验证码处理
- 不要做代理池
- 不要大规模重构项目目录
- 不要删除已有可运行代码
- 不要修改与当前任务无关的文件
- 不要引入大型依赖
- 不要写伪代码

## 4. 开发原则

1. 一次只做一个小任务
2. 每个任务必须有明确验收标准
3. 每次修改后必须输出修改文件列表
4. 每次修改后必须给出验证命令
5. 后端优先于前端
6. MockCollector 优先于 PlaywrightCollector
7. 规则引擎优先于 LLM
8. 可运行优先于好看
9. 最小改动优先
10. 报错时只修复当前错误，不顺便开发新功能

## 5. 当前优先级

### P0

- 项目骨架
- FastAPI 初始化
- SQLAlchemy 配置
- Alembic 配置
- 7 张核心表
- 监控源 CRUD
- MockCollector
- 线索识别规则引擎
- 触发采集完整链路
- 线索查询和导出
- 今日报告生成

### P1

- 前端 P0 页面
- 今日获客作战台
- 同行账号发现池
- Playwright manual_post 指定链接采集

### P2

- 真实平台采集
- 定时任务
- 多客户管理
- 团队协作
- 简单权限

## 6. 每次任务完成后必须输出

- 修改了哪些文件
- 主要实现了什么
- 如何启动
- 如何验证
- 是否有风险
- 下一步建议

## 7. 报错修复规则

遇到报错时：

1. 先分析原因
2. 只做最小修复
3. 不重构
4. 不新增无关功能
5. 修复后给验证命令
