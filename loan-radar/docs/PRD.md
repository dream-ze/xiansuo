# PRD：助贷线索雷达 MVP

## 作用

记录助贷线索雷达 MVP 的产品目标、采集边界、验收标准和后续路线。本文档以当前代码能力为准：MediaCrawler 为唯一可用采集器，支持小红书、抖音、知乎三个平台。

## 当前阶段

当前阶段是"助贷线索雷达 MVP"，面向客户可试用、可交付、愿意付费。

已具备的核心链路：

监控源管理 → 采集任务 → MediaCrawler 采集 → 帖子池 → 评论池 → 线索识别 → 线索池 → 今日获客报告 → CSV 导出 → 同行账号发现池

本阶段采集能力：

- **关键词搜索采集**：用户输入关键词，系统通过 MediaCrawler 在指定平台搜索帖子并采集内容和评论。
- **指定帖子采集**：用户输入帖子链接，系统通过 MediaCrawler 采集该帖子的内容和评论。
- **创作者主页采集**：用户输入创作者主页链接，系统通过 MediaCrawler 采集该创作者的帖子。

## 产品目标

1. 通过 MediaCrawler 开源项目实现多平台真实采集（当前支持小红书、抖音、知乎）。
2. 保持采集失败可控：失败写入采集任务，不影响后端服务。
3. 让业务用户能在前端看到真实采集源、采集状态、帖子、评论、线索和失败原因。
4. 线索管理支持完整状态流转：新线索 → 已跟进 → 有意向 → 无效 / 已转化。
5. 今日报告面向客户可读，包含扫描概况、A级线索详情、典型证据、建议话术、同行发现、明日建议。
6. 同行账号发现池支持审核通过后加入监控源。

## 范围边界

### 本阶段做

1. `keyword` / `competitor_account` / `manual_post` / `hot_post_rule` 监控源均使用 `config.collector_type = "media_crawler"`。
2. MediaCrawler 支持小红书、抖音、知乎三个平台的关键词搜索、指定帖子、创作者主页采集。
3. 创建监控源时后端校验平台与 collector_type 兼容性，media_crawler 仅允许 xhs/douyin/zhihu。
4. 前端监控源页默认 collector_type 为 media_crawler，平台选项仅展示 xhs/douyin/zhihu，创建时提示依赖 MediaCrawler API 服务。
5. 采集需 MediaCrawler API 服务在线（默认 `http://127.0.0.1:8080`）。
6. 帖子/评论去重，避免重复入库。
7. 评论为空允许采集成功，线索数可以为 0。
8. 错误信息脱敏，采集失败不暴露内部细节。
9. 帖子池、评论池、采集任务页支持核验采集结果。
10. 线索池支持完整状态流转（new/contacted/interested/invalid/converted）、备注、来源帖子双向导航和 CSV 导出。
11. 今日获客报告包含：扫描概况、A级线索详情、典型证据、建议跟进话术、发现的同行账号、明日建议。
12. 同行账号发现池前端页面已挂载路由，支持查看、通过、忽略同行账号，通过后可加入监控源。
13. Smoke Test 覆盖完整链路验证。

### 本阶段不做

1. 不做 Mock 采集器路由（代码存在但 Factory 不路由，仅保留文件供参考）。
2. 不做 Playwright 采集器路由（代码存在但 Factory 不路由）。
3. 不做 ExternalApiCollector 路由（代码存在但 Factory 不路由）。
4. 不做 GenericWebCollector 路由（代码存在但 Factory 不路由）。
5. 不做登录态采集绕过。
6. 不做验证码处理。
7. 不做代理池、Cookie 池、账号池。
8. 不做指纹伪装、风控绕过、反爬绕过。
9. 不新增 CRM、员工管理、自动发布、复杂权限或智能体编排。

## 用户流程

1. 用户进入监控源管理页。
2. 创建监控源，选择平台（小红书/抖音/知乎）、source_type、关键词或链接。
3. collector_type 默认为 `media_crawler`，页面提示依赖 MediaCrawler API 服务。
4. 点击"立即采集"。
5. 系统通过 MediaCrawler API 采集帖子和评论。
6. 采集成功：系统写入帖子和评论，对评论执行线索识别。
7. 采集失败：采集任务标记为 `failed`，展示脱敏后的错误原因。
8. 用户在帖子池、评论池、线索池、今日报告中查看结果。
9. 用户在线索池中管理线索状态（新线索/已跟进/有意向/无效/已转化），添加备注，导出 CSV。
10. 用户在今日报告中查看扫描概况、A级线索详情、典型证据、建议话术、同行发现、明日建议。
11. 用户在同行发现页审核同行账号，通过后加入监控源。

## 验收标准

1. MediaCrawler 服务在线时，关键词搜索采集链路可跑通（小红书/抖音/知乎）。
2. 指定帖子链接采集可跑通。
3. 采集失败时后端不崩溃，采集任务有清晰脱敏的 `error_message`。
4. 前端构建通过，监控源页能创建 media_crawler 采集源，平台选项仅展示 xhs/douyin/zhihu。
5. 后端校验平台与 collector_type 兼容性，不支持的组合返回 400。
6. 帖子池能打开原链接，评论池能按帖子 ID 核验评论。
7. 线索池支持完整状态流转、备注、来源帖子双向导航和 CSV 导出。
8. 今日报告可生成和展示，包含 A级线索详情、典型证据、建议话术、同行发现、明日建议。
9. 同行账号审核页面可访问，支持通过/忽略操作。
10. Smoke Test 全链路 PASS。

## 后续路线

1. 恢复 MockCollector 到 Factory 路由，保证无 MediaCrawler 服务时演示可跑。
2. 扩展 MediaCrawler 支持更多平台（快手、B站、微博、贴吧）。
3. 增加 ExternalApiCollector，接入合规第三方采集服务。
4. 增加 GenericWeb selector 配置能力。
5. 增加定时采集调度和异步采集队列。
6. 增加平台专用 parser，继续遵守公开、低频、可控、无绕过原则。
7. 线索自动分配和跟进提醒。
8. 多租户和基础权限。
