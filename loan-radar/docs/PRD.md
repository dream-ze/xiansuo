# PRD：线索雷达真实采集 MVP

## 作用

记录线索雷达 Demo 可成交版的当前产品目标、真实采集边界、验收标准和后续路线。本文档以当前代码能力为准：保留 Mock 主链路，并新增 `manual_post + playwright` 的公开帖子链接采集 MVP。

## 当前阶段

当前阶段是“Mock 主链路 + 指定公开帖子真实采集”。

已具备的核心链路：

监控源管理 -> 采集任务 -> Mock / Playwright 采集 -> 帖子池 -> 评论池 -> 线索识别 -> 线索池 -> 今日获客报告 -> CSV 导出 -> 同行账号发现池。

本阶段真实采集只解决一个明确场景：用户手动输入公开可访问的帖子 URL，系统尝试采集帖子内容和公开评论，并复用现有线索识别、日报和导出能力。

## 产品目标

1. 让演示不再只依赖 Mock 数据，可以用一条公开帖子链接验证真实内容进入系统。
2. 保持采集失败可控：失败写入采集任务，不影响后端服务和 Mock 链路。
3. 让业务用户能在前端看到真实采集源、采集状态、帖子、评论、线索和失败原因。
4. 为后续 External API、Generic Web、平台专用解析器预留边界，但不在本阶段实现大规模平台采集。

## 范围边界

### 本阶段做

1. `manual_post` 监控源支持 `config.collector_type = "playwright"`。
2. `PlaywrightCollector` 只采集 `http/https` 公开页面。
3. 解析器边界拆分为 `BasePageParser`、`GenericPostParser`、`PageParserFactory`。
4. 通用解析器提取标题、正文、作者、评论，并输出现有 `CollectedPost` / `CollectedComment`。
5. 评论为空允许采集成功，线索数可以为 0。
6. 创建或更新监控源时拒绝非 `manual_post` 使用 `playwright`。
7. 前端新增真实指定链接采集提示，避免用户误把关键词采集切到 Playwright。
8. 帖子池、评论池、采集任务页支持核验真实采集结果。
9. 增加最小后端测试和 smoke / build 验证路径。

### 本阶段不做

1. 不做关键词真实搜索采集。
2. 不做登录态采集。
3. 不做验证码处理。
4. 不做代理池、Cookie 池、账号池。
5. 不做指纹伪装、风控绕过、反爬绕过。
6. 不承诺小红书、抖音、知乎页面稳定直连。
7. 不新增 CRM、员工管理、自动发布、复杂权限或智能体编排。

## 用户流程

1. 用户进入监控源管理页。
2. 选择“指定帖子链接”。
3. 输入平台、名称和公开帖子 URL。
4. 默认使用 `Playwright` 采集器。
5. 点击新增，再点击立即采集。
6. 如果成功，系统写入帖子和评论，并对评论执行线索识别。
7. 如果失败，采集任务标记为 `failed`，展示错误原因。
8. 用户在帖子池、评论池、线索池、今日报告中查看结果。

## 验收标准

1. Mock keyword 采集链路仍可跑通。
2. `manual_post + playwright` 非 http/https URL 会被拒绝。
3. `keyword + playwright` 会被拒绝，避免误做真实关键词采集。
4. 公开页面能解析出帖子时，即使评论为空也可成功入库。
5. 真实采集失败时后端不崩溃，采集任务有清晰 `error_message`。
6. 前端构建通过，监控源页能创建真实指定链接采集源。
7. 帖子池能打开原链接，评论池能按帖子 ID 核验评论。
8. 后端测试覆盖采集器选择、监控源校验、通用解析器。

## 后续路线

1. 增加 ExternalApiCollector，接入合规第三方采集服务或用户自有采集服务。
2. 增加 Generic Web selector 配置能力。
3. 增加去重和增量采集，避免重复入库和重复生成线索。
4. 增加平台专用 parser，但必须继续遵守公开、低频、可控、无绕过原则。
